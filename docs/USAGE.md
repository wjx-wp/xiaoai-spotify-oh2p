# 使用说明

本文说明已经完成部署的 `OH2P + 1.56.20` 主路径如何日常使用。它不是刷机教程；开始前，音箱应已通过健康检查，Android 应用也应已完成安全配对和 Spotify 授权。

## 日常工作方式

- librespot 直接运行在音箱上，电脑不需要常开。
- 唤醒词和语音识别仍由原生“小爱同学”处理；表中的说法会提前路由，其他被小米云最终确认为 `MUSIC` 的请求也会兜底转给 Spotify。
- 米家设备、红外、天气、闹钟和其他非音乐请求继续交给原生小爱。
- 手机 Spotify 仍是完整的可视化遥控器，可以选歌、编辑队列、拖动进度和控制 Spotify Connect 音量。
- Android 伴侣应用可以在满足安全条件时，把手机当前的 Spotify 会话转移到音箱。

## 中文语音指令

下表中的说法均需先说“小爱同学”。唤醒词不会进入项目的命令匹配，因此表中只列唤醒词之后的内容。

### 播放内容

| 说法示例 | 精确语义 |
| --- | --- |
| `播放周杰伦` | 同时搜索艺人和歌曲；艺人名称完全相同时播放该艺人，否则优先播放第一首匹配歌曲。 |
| `播放周杰伦的歌` | 把“周杰伦”作为艺人搜索并播放艺人上下文。 |
| `播放歌手周杰伦`、`播放艺人周杰伦` | 只搜索艺人。 |
| `播放歌曲晴天`、`播放一首晴天` | 只搜索单曲，播放第一项 Spotify 搜索结果。 |
| `播放专辑叶惠美` | 只搜索专辑，播放第一项结果的专辑上下文。 |
| `播放歌单华语经典` | 搜索 Spotify 全站歌单，播放第一项结果。 |
| `播放我的歌单通勤` | 只搜索当前 Spotify 账号的歌单；依次采用完全同名、名称包含搜索词的第一项。 |
| `播放我的歌单` | 播放当前账号返回的第一个歌单。 |
| `播放`、`播放音乐`、`播放歌曲` | 从个人音乐池选择种子并启动随机、持续播放。 |
| `随便播放一首歌曲`、`来一首歌`、`来点音乐`、`听点歌`、`推荐点歌` | 从 Spotify 常听与点赞内容组成的个人音乐池启动 Radio。 |

播放前缀还可以使用 `帮我播放…`、`请播放…`、`给我播放…`、`播放一下…`、`放一下…` 或 `放…`。内容开头可以加 `Spotify`、`spotify` 或 `声破天`，例如 `播放 Spotify 歌手周杰伦`。

搜索播放会立即中断同一轮原生音乐回答，并停止小米原生播放器，避免 QQ 音乐会员提示或试听版抢占扬声器。即使本地词典没有识别一句音乐说法，只要小米云最终返回 `audio_type=MUSIC`，原生音乐也会被底层拦截，并使用同轮文本回补 Spotify；无法精确解析时启动个人 Radio。搜索结果由 Spotify 返回；同名歌曲较多时，使用 `歌曲`、`歌手`、`专辑` 或 `我的歌单` 限定类型会更确定。

### 自动续播与个人 Radio

Spotify Web API 没有可供本项目可靠切换的官方 Autoplay 开关，因此音箱不依赖客户端的隐藏状态。每日点赞同步会额外生成最多 100 首的个人音乐池，来源依次为 Spotify 中期常听歌曲和已点赞歌曲。播放单曲或泛化音乐请求时：

- 目标单曲作为 Radio 种子；
- 种子与个人池写入账号内的私有 `XiaoAI · Radio` 歌单；
- 启动随机播放和列表循环，单曲结束后一定仍有下一首；
- 再次同步会刷新个人池，手机端点赞变化最迟每日进入候选集合。

`XiaoAI · Radio` 由程序管理，请不要手工编辑。它不是 Spotify 官方推荐算法的完整复刻，但比依赖 Connect 客户端是否下发 Autoplay 更稳定。

### 点赞/收藏音乐

以下内容名称在本项目中都表示 Spotify 的“已点赞歌曲”：

`点赞音乐`、`点赞歌曲`、`点赞的音乐`、`点赞的歌曲`、`我点赞的音乐`、`我点赞的歌曲`、`收藏音乐`、`收藏歌曲`、`收藏的音乐`、`收藏的歌曲`、`我喜欢的音乐`、`我喜欢的歌曲`、`喜欢的歌`、`我的收藏`、`我的音乐`。

在前面加播放前缀即可，例如：

- `播放点赞音乐`
- `播放我喜欢的音乐`
- `请播放我的收藏`

`随机播放点赞音乐`、`随机播放点赞歌曲`、`随机播放收藏音乐` 和 `随机播放我喜欢的音乐` 会先播放点赞镜像歌单，再打开随机播放。

### 播放控制

| 说法 | 动作 |
| --- | --- |
| `闭嘴`、`停止`、`暂停`、`暂停播放`、`暂停音乐`、`停止播放`、`停止音乐`、`关闭音乐`、`关掉音乐`、`把音乐关了`、`音乐关掉`、`别放了`、`不要播放了` | 暂停 Spotify。 |
| `继续`、`继续播放`、`继续音乐`、`恢复播放` | 恢复 Spotify。 |
| `下一首`、`下一曲`、`切歌` | 下一首。 |
| `上一首`、`上一曲` | 上一首。 |
| `随机播放`、`打开随机播放`、`开启随机播放` | 打开当前 Spotify 上下文的随机播放。 |
| `关闭随机播放`、`不要随机播放` | 关闭随机播放。 |
| `单曲循环` | 循环当前单曲。 |
| `列表循环`、`歌单循环` | 循环当前播放上下文。 |
| `关闭循环`、`不要循环` | 关闭循环。 |

播放、暂停、上一首和下一首会优先走音箱内的本地 Spirc 控制通道；本地通道不可用时才回退到 Spotify Web API。

## 点赞歌曲每日镜像

Spotify 的“已点赞歌曲”不是普通歌单。为获得完整、可随机和可持续播放的上下文，音箱会在你的账号中维护一个名为 `XiaoAI · Liked Songs` 的**私有歌单**：

- 同步服务每小时检查一次；距离上次成功同步达到 24 小时时才真正同步。
- 同步会读取全部已点赞歌曲，并完整重写镜像歌单；不要手动编辑这个歌单，手工更改会在下次同步时被覆盖。
- 手机上新增或取消点赞不会逐秒反映到镜像中，最迟在下一次成功的每日同步后生效。
- 首次尚未成功建立镜像时，`播放点赞音乐` 会临时播放 API 返回的前 50 首点赞歌曲。

需要立刻同步时可以说：

- `同步点赞音乐`
- `同步点赞歌曲`
- `同步收藏音乐`
- `同步收藏歌曲`
- `刷新点赞音乐`
- `刷新收藏音乐`

同步期间不要反复发出相同命令；大量收藏需要分页读取并按每批最多 100 首重写歌单。

## 当前能力边界

以下边界以 OH2P 设备端主路径为准。仓库中的 `src/` 是早期电脑端兼容性研究代码，不代表音箱当前已经提供同名功能。

| 功能 | 当前状态 |
| --- | --- |
| 播放/暂停、上/下一首 | 支持语音；中央播放键也支持播放/暂停切换。 |
| 搜索歌曲、艺人、专辑、公开歌单、我的歌单 | 支持语音。 |
| 随机、单曲循环、列表循环 | 支持语音。 |
| Spotify 队列 | 可在手机 Spotify 中管理；当前没有添加、删除或朗读队列的语音指令。单曲与泛化请求会建立最多 100 首的私有 Radio 上下文。 |
| 最近播放 | 当前没有语音指令。授权范围中虽包含读取权限，设备端主路径尚未调用该接口。 |
| 常听歌曲/艺人 | 中期常听歌曲会进入个人 Radio 候选池；当前没有单独朗读或列出常听内容的语音指令。 |
| 当前歌曲 | 在手机 Spotify 中查看；当前没有“这是什么歌/正在播放什么”的 OH2P 语音响应。原生小爱也不知道 librespot 正在播放的内容。 |
| 音量 | 音箱实体音量键及原生小爱控制硬件/混音器音量；Spotify 应用内的设备滑块控制 Spotify Connect 音量。当前没有把“Spotify 音量调到…”路由到 Web API 的设备端语音指令。 |

## 原生小爱、米家和红外

本地词典匹配或小米云最终确认为 `audio_type=MUSIC` 的播放会被接管。其他请求继续走小米原生链路，例如：

- `打开客厅灯`、`关闭卧室灯`
- 已在小米平台配置好的红外家电控制
- 天气、时间、闹钟和普通问答

项目不会把整套小爱替换掉，也不会让 Spotify 取得米家或红外权限。若一句话同时包含设备控制和音乐播放，不保证能够拆成两个动作，请分开说。

## 实体按键

- 中央播放键：在 Spotify 播放与暂停之间切换。按键桥直接向 librespot 的本地 Unix socket 发送 `toggle`，正常情况下无需访问互联网控制接口。
- 原生触控进程仍会收到按键事件，但过滤器仅禁止它启动小米原生播放器；因此不会故意同时播放两套音乐。
- 音量、静音和传感器能力仍由原生触控进程处理。
- 当前部署没有把其他实体键映射成 Spotify 上一首或下一首；这两个动作请使用语音或手机 Spotify。
- 本地 socket 不可用时，中央播放键会回退到 Spotify Web API，并在短时间内多次停止原生播放器；此时按键响应会明显慢一些。

## Android 自动接管

### 必须完成的设置

1. 在“小爱 Spotify 接管”应用中保存音箱当前的家庭局域网 IPv4 地址，确认状态为“已通过固定主机指纹和手机签名密钥认证”。
2. 打开应用中的“启用自动接管”。
3. 在 Android 系统无障碍设置中启用“Spotify 启动预接管”。此服务只接收 Spotify 的窗口切换事件，配置为不能读取窗口内容。
4. 在 Spotify 设置中打开 `Device Broadcast Status`，让 Spotify 发送播放状态广播。

Android 13 及以上的通知权限不是播放或接管所必需，但建议允许，否则收不到 Spotify 授权预计到期提醒。网络访问和网络状态是安装时自动授予的普通权限，不需要文件存储、联系人、麦克风或定位权限。

### 自动接管发生的条件

只有以下条件同时满足时，应用才会自动请求接管：

- 自动接管开关已启用；
- 手机当前活动网络是 Wi-Fi，并且没有叠加 VPN；
- 保存的音箱地址可达，SSH 主机指纹与构建时固定的指纹完全一致，手机公钥也已在音箱上完成受限配对；
- 没有连接有线耳机、蓝牙耳机/音箱、助听设备、车载、USB 音频、HDMI、底座或其他外部私密音频输出。

打开 Spotify 窗口时，无障碍服务会立即做一次“预接管”。在 Android 14 及以上，经过发送方校验的“开始播放”广播还会在约 0.5 秒和 2.5 秒各尝试一次；较旧 Android 无法可靠确认广播发送方，因此不会使用这条广播，只依赖窗口预接管。应用中的“测试接管”按钮可以用于检查家庭网络、配对和音箱状态。

接管发送的是固定的受限 SSH 命令，音箱再通过本地 Spirc 把现有 Spotify 会话转移到自己；手机没有音箱 root shell 权限。

## Spotify 重新授权

音箱会自动用 refresh token 换取短期 access token，平时不需要每小时手工登录。项目按授权日起 180 天**估算**重新授权日期；这是本地提醒值，不是 Spotify 对令牌寿命的承诺，Spotify 仍可能提前撤销授权。

日常重新授权流程：

1. 打开“小爱 Spotify 接管”应用，查看“Spotify 授权”区域。
2. 点“重新授权 Spotify”。系统浏览器会打开 Spotify 官方授权页。
3. 登录创建该 Client ID 时允许使用的 Spotify Premium 账号，确认授权。
4. 返回应用。应用先向 Spotify 官方进行只读验证，再通过受限 SSH 把 refresh token 下发给音箱。
5. 看到“Spotify 已授权并安全下发到音箱”后完成。成功下发后，手机会删除临时 access token 和 refresh token，只保留授权日期。

如果浏览器授权已经成功，但官方验证或下发临时失败，请先点“重新验证并下发”或“重试下发已验证授权”，不要连续创建多轮新授权。应用会对待重试的授权材料加密保存，并在过期或不合法时自动丢弃。

Android 应用构建时注入的 Spotify Client ID 必须和音箱 `spotify-web.env` 中的 Client ID 相同；PKCE 不使用 Client Secret。

## 查看健康状态

在音箱的可信 root SSH 会话中运行：

```sh
/data/xiaoaimusic/healthcheck.sh
```

工程主机已按仓库约定配置本地凭据时，也可以从 WSL 运行：

```sh
bash host/device-status.sh <音箱局域网IP>
```

健康输出至少应满足：

- `librespot`、`supervise-librespot`、`voice-bridge.sh`、`xiaoaimusic-keybridge` 和 `supervise-liked-sync.sh` 都有进程；
- `/tmp/xiaoaimusic-librespot-control.sock` 存在；
- `legacy_home_bridge=inactive port=18789`；
- `mobile_auth_bind=active`；
- `mico_aivs_lab` 映射了 `libxiaoaimusic_aivs_filter.so`，`touchpad` 映射了 `libxiaoaimusic_touchpad_filter.so`；
- `authorization_marker=clear`；
- `SPOTIFY_AUTH status=AUTH_OK reauthorization_required=no`；
- 最后出现 `SPOTIFY_API_READY`，设备名和 `device.env`/`spotify-web.env` 中的名称一致。

`estimated_expires_at` 和 `estimated_remaining_days` 只是按 180 天计算的提醒。`last_sync_epoch` 是点赞镜像最后一次成功同步的 Unix 时间。Android 应用首页还会显示配对、预计授权期限和最近一次接管结果。

出现异常时参见[故障排除](TROUBLESHOOTING.md)。
